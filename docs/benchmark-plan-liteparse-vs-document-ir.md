# LiteParse 原生格式 vs Duon Document IR 基准测试方案 (Benchmark Plan)

> **文档定位**：Duon 格式对比与性能评估标准规范  
> **核心目标**：通过严格的控制变量法，量化对比 LiteParse 原生输出格式与 Duon Document IR 格式在大模型结构化抽取、空间坐标溯源、Token 消耗、推理时延及容错鲁棒性上的真实表现。

---

## 1. 核心命题与对比组设定

在文档智能处理中，底层解析器（如 LiteParse）负责解析 PDF 底层算子并还原字符几何位置，而上层认知系统（LLM）负责语义理解与业务提取。

本测试旨在验证：**中间引入 Document IR 是否真正比直接使用底层解析器输出更具备精度、成本与工程落地优势。**

### 实验对照组设计

| 对照组标识 | 数据源格式 | 注入 LLM 上下文形态 (Prompt Context) | 证据坐标溯源机制 |
| :--- | :--- | :--- | :--- |
| **方案 A<br>(对照组 1：原生 JSON 直传)** | `lit parse --format json`<br>原生机器输出 | 原始 JSON 序列化字符串<br>（包含 `x, y, width, height`, 字体名, 字号等完整元数据） | 要求大模型直接在输出的 JSON 中预测浮点外接矩形 `[x0, y0, x1, y1]` |
| **方案 B<br>(对照组 2：纯文本 + 模糊回查)** | `lit parse --format text`<br>纯文本流式抽取 | 纯文本换行字符串 | 要求大模型输出引用原文（Quote），由后端在 LiteParse 的 `text_items` 中进行字符串包含或模糊匹配反查坐标 |
| **方案 C<br>(实验组：Duon Document IR)** | `LiteParseAdapter` 规整后的 `DocumentIR` | 经 `ContextBuilder` 投影的离散空间锚点文本（`[p1_i0001] 文本内容...`） | 大模型仅需输出引用条目 ID（如 `citations: ["p1_i0008"]`），由 Duon 引擎查表以 $O(1)$ 复杂度确定性还原物理矩形框 |

## 2. 评测多维量化指标 (Evaluation Metrics)

评测杜绝主观臆断，全部采用可编写程序自动计算的客观物理指标：

### 2.1 成本与效率指标 (Cost & Efficiency)
1. **Context Token 占用量**：输入给大模型的 Prompt Token 总数（使用 `tiktoken` 或目标模型的官方分词器精确计量）。
2. **Token 压缩率 / 降噪比**：
   $$\text{Compression Rate} = \frac{\text{Token}_{\text{方案A}} - \text{Token}_{\text{测试方案}}}{\text{Token}_{\text{方案A}}} \times 100\%$$
3. **端到端推理耗时 (Latency P50 / P95)**：从发起 LLM 请求到完成结构化校验与坐标绑定的全链路耗时。

### 2.2 语义抽取质量 (Semantic Extraction Quality)
1. **字段级精准度 (Precision / Recall / F1-Score)**：对比人工标注的标准答案（Ground Truth），统计关键业务字段（订单号、甲方、乙方、金额、完成时间、制作内容等）的抽取正确率。
2. **小模型抗噪能力 (Robustness on 7B/14B)**：在浮点数与底层渲染噪音干扰下，中小型开源模型是否会出现注意力分散、关键字段漏提取或输出格式崩溃。

### 2.3 几何坐标溯源质量 (Evidence & Coordinate Fidelity)
1. **交并比 (IoU - Intersection over Union)**：
   $$\text{IoU} = \frac{\text{Area}(\text{预测 BBox} \cap \text{真值 BBox})}{\text{Area}(\text{预测 BBox} \cup \text{真值 BBox})}$$
   - $\text{IoU} \ge 0.8$ 视为高精度命中（精准框中文字）；
   - $0.5 \le \text{IoU} < 0.8$ 视为粗略命中；
   - $\text{IoU} < 0.5$ 视为错位失效。
2. **同名实体/重复值错配率 (Ambiguity Collision Rate)**：
   - 当同一文档中多次出现相同金额（如“1600元”在单价、定金、总金额多处出现）或相同人名时，溯源坐标是否选对了真实对应的条款段落。
3. **坐标伪造/幻觉率 (Coordinate Hallucination Rate)**：
   - 模型预测的坐标是否超出页面物理边界、面积为 0、或框选区域根本无真实文字。

## 3. 测试数据集规划 (Benchmark Dataset)

测试集选取 4 类覆盖典型业务难点的真实商业 PDF，每类样本均预先建立包含**标准字段值**与**标准物理像素外接矩形**的 Ground Truth 标注集：

| 数据集分类 | 样本数量 | 典型样本特征 | 核心评测挑战 |
| :--- | :---: | :--- | :--- |
| **D1：高密度单页委托单 / 采购订单** | 10 份 | 如 `2026-G-D-030.pdf`，包含需求人、合同金额、签字盖章区域 | 多处重复金额/人名定位、密集 Key-Value 排版 |
| **D2：复杂行列跨页财务表格** | 5 份 | 采购清单明细、对账单、工程量清单 | 跨行跨列单元格对齐、密集数字流、表头表体映射 |
| **D3：图文/双栏混排商业合同** | 5 份 | 框架服务协议、劳动合同、条款说明书 | 左右双栏排版、跨栏阅读顺序干扰、印章文字混叠 |
| **D4：长文档 (10~20 页)** | 3 份 | 招投标说明书、年度审计报告 | 长文本窗口压力、大海捞针（Needle in a Haystack）注意力稀释 |

## 4. 评测模型阶梯 (Model Matrix)

为确保测试结论在不同算力规模下的普适性与客观性，测试覆盖高中低三个模型梯度：

1. **轻量级端侧开源模型**：`Qwen2.5-7B-Instruct` / `Llama-3.1-8B-Instruct`  
   - *评测重点*：在浮点噪声极大时的表现崩溃率，验证降噪与离散锚点对小模型的提效幅度。
2. **主流工业级开源模型**：`Qwen2.5-14B/32B-Instruct` / `DeepSeek-V3`  
   - *评测重点*：企业私有化部署主力模型的性价比与稳定性平衡点。
3. **顶配闭源大模型**：`GPT-4o` / `Claude 3.5 Sonnet`  
   - *评测重点*：最强推理能力下的坐标幻觉基线，以及大规模商用时的 Token 成本节省比率。

## 6. 后续实施路径 (Implementation Roadmap)

本方案当前已固化归档，后续实施时将按以下三步推进：
1. **阶段一（真值集构建）**：准备 5~10 份测试 PDF 样本，编写 JSON 格式的 Ground Truth 标注文件（字段标准值 + 标准 BBox 坐标）。
2. **阶段二（评测脚本编写）**：在 `crates/extractor` 或独立评测工具中，实现三组方案的 Prompt 组装器、Tokenizer 计数器与 IoU 计算模块。
3. **阶段三（自动化跑批与报告发布）**：自动化批处理调用指定模型，生成完整的 CSV 统计表与对比可视化图。
